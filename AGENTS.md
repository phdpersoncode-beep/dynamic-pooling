# Goal

Our goal is to make this dynamic token pooling transformer implementation **efficient** in two ways:
- use optimized transformer layers and self-attention implementations with things like flashattention2
- use KV-caching to speed up inference

We want to create a toy sequence representation with a custom tokenizer for a three-level hierarchy using a generalization of the whitespace boundary rule of the dynamic token pooling transformer.

I'd like to have tokens x0, x1, x2, x3, ..., x255 and boundary tokens b1, b2, and b3. b1 would indicate a boundary in the first hierarchy level, b2 in the second, and b3 in the third. 

A boundary token at position t means that the boundary **is after** the current position (between  x_t and x_{t+1}). 

I want to have the following architecture with residual connections:
- transformer layers
- downsampling according to b1
- transformer layers
- downsampling according to b2
- transformer layers 
- downsampling according to b3
- transformer layers
- upsampling according to b3
- transformer layers
- upsampling according to b2
- transformer layers
- upsampling according to b1
- transformer layers

Let's focus on the KV-caching implementation first. You will probably be in a CPU-only environment so we don't care about training or running flashattention2 yet. Follow the plan outlined in the TODOs below.

Where the verb goes

At the space after Red, only L1 closes. After foxes, L1 closes the word and L2 closes the adjective–noun phrase. After run., all three close. The second clause repeats the pattern with Gray owls and hunt.

There is a subtle choice here. In this model every completed L3 group is made of completed L2 children. “Red foxes run.” therefore has two L2 children, Red foxes and a one-word verb group, run. If a separate linguistic annotation should flag only adjective–noun phrases, keep that phrase label alongside the structural masks. Supplying (1,0,1) at the verb would leave its L2 group unfinished when L3 tries to close.

For this fixture, punctuation stays with the verb and the author includes a space after each period, including the final one. SOS and EOS each occupy one special-token position with three zero marks. SOS participates in the first word mean. Each processed lower-level null contributes to the first parent mean at the next level. EOS leaves open groups open.

What we hand the model

Imagine four strips of equal length laid on top of each other. The first holds character IDs. The others hold the author’s L1, L2 and L3 marks. A single step reads one column. Training and prompt prefill read a block of columns. A resumed session starts at the next column.

position 10   token ID for ␠    1  1  0
position 11   token ID for r    0  0  0

These two rows show the original fixture. Each occurrence of ␠ uses the same vocabulary ID. Its three supplied values can differ. For a batch, each strip has shape [time, batch]. A cached step takes one [batch] row from each strip. The display counts completed groups and illustrates the seven-stack schedule for consumed inputs. The model also keeps a separate initial null slot at each pooled stack.

Already implemented. HourglassLM.forward(data, c1, c2, c3), step_batched(state, tokens, c1, c2, c3) and prefill_batched(model, data, c1, c2, c3) already take these values. The toy training loader also reads three saved arrays. A new character vocabulary needs a matching ID map and model vocabulary size.

What needs to change. The greedy decoders accept a prompt and tokenizer and calculate the marks. CacheSession.consume(data) also computes them internally. Give these entry points an explicit-array option, including one supplied triple per newly consumed character during continuation. Bind the user’s character map and mask convention to the dataset and checkpoint so saved examples mean the same thing after reload.

What to test next

  1. Commit the four strips as a fixture. Supply the three literal Boolean arrays. Assert their shape, binary values, and L3 ≤ L2 ≤ L1 at every position. Check both clause trees against hand-written memberships. A grammar parser or boundary predictor is unnecessary for this test.
  2. Carry exactly those marks through every entry point. Test the same character IDs with two different valid annotations in one batch. At each prefix compare the cached member to its own full-prefix result. Split just before and after a word, noun phrase, and clause closes. Save, restore, and consume the next annotated column.
  3. Check what the cache remembers. Compare real per-layer keys and values, open sums and counts, latest completed groups, finite next-token logits, and greedy choices. The CLI currently compares generated token IDs only. Keep FP32 and BF16 counterexamples visible.
  4. Test recall after the source clause closes. Put a source in the first clause, add a distractor, then score recall in a later group. Assert the source L3 slot is available before the first scored prediction. Give the flat control access to the same boundary annotations.
